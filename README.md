# PhotoShelf Ultra v1.11.1

Локальный менеджер фото и видео для Windows x64, C# / .NET 10 / WPF.
Реализованы этапы P0: быстрое измеримое ядро и безопасная организация файлов.

Подготовка выпуска **1.11.1-ultra**: исправлен потерянный повторный запрос фонового
визуального индексатора. Новый номер позволяет установленной 1.11 предложить обновление
после публикации подписанного релиза. [Состав, ограничения и порядок выпуска](docs/v1.11.1-release.md).

## Запуск

Актуальные исходники и история изменений: [BigGluk23/PhotoShelf](https://github.com/BigGluk23/PhotoShelf).
Для Windows скачайте артефакт `PhotoShelf-win-x64` успешного запуска [Windows CI](https://github.com/BigGluk23/PhotoShelf/actions/workflows/windows-ci.yml), распакуйте ZIP и запустите `PhotoShelf.exe`.
.NET runtime, иконки и PNG интерфейса встроены в EXE. Сохраняйте рядом папку `codecs/heif`: в ней встроенный HEIC-декодер. Устанавливать кодеки Windows не нужно.
Рабочий каталог и журналы находятся в отдельной папке `%LOCALAPPDATA%\PhotoShelf\storage-generations\<id>`. При первом обновлении прежний каталог копируется и проверяется; исходная папка Local/Roaming сохраняется. При двух библиотеках программа предлагает выбрать источник, без автоматического объединения. Выбор закреплён в `storage-selection-v1.json`. Кэш и новая диагностика находятся в LocalAppData. Карантин выбирается явно перед первым использованием.
Сканирование и просмотр не изменяют содержимое оригиналов.

## Похожие фотографии

Кнопка «Дубликаты» теперь разделяет два независимых режима. «Точные дубли» по-прежнему
подтверждаются SHA-256 и могут быть безопасно перенесены в карантин. «Похожие фото»
используют фоновый визуальный индекс, показывают серии карточками и ничего не удаляют и
не помечают автоматически. Искать можно в текущем виде, отмеченных папках, текущей папке,
во всей библиотеке или только между двумя выбранными папками. Пока индекс пополняется,
экран честно показывает, сколько фотографий уже участвовало в сравнении.

Выбор точных дублей хранится в отдельной дисковой сессии и не сбрасывается при
перелистывании. Правила «оставить новую копию», «оставить короткий путь» и «папка в
приоритете» применяются ко всему снимку без загрузки всех групп в интерфейс. Массовая
отметка сначала открывает полный план карантина. Большая операция выполняется безопасными
порциями: для каждой порции заново проверяются и удерживаются открытыми сохраняемые копии,
пишется отдельный durable-журнал, а восстановление и откат остаются в окне «Операции».
Прямого удаления нет.

## Обновления из интерфейса v1.11

«Настройки → Обновления программы»: отключаемая проверка стабильных GitHub Releases при запуске, ручная кнопка, отсрочка и пропуск версии. Проверки работают в фоне и не показывают сетевых ошибок. Загрузка запускается только по кнопке; установка требует отдельного действия «Обновить и перезапустить». Сохранённый пакет и старый запрос никогда не становятся автоматическим согласием.

Пакет проверяется по встроенному открытому ключу RSA и SHA-256. Обновлятор ожидает фактическое завершение приложения, создаёт отдельную папку программы, проверяет её запуск на изолированном каталоге и переключает указатель версии. Оригиналы, каталоги, журналы и предыдущие программы не удаляются и не заменяются. Ошибка после запуска новой программы не вызывает автоматическую подмену БД старой копией.

Канал релизов включается после отдельной настройки ключа подписи и явной публикации проверенного выпуска. Выпуск требует защищённого окружения GitHub `release`, независимого подтверждения владельца и двух Windows-проверок полного перехода между версиями и прерывания установщика. Публичная публикация не выполняется обычным push. При подготовке 1.11.1 4 октября 2026 подтверждены обязательное ревью `main` и защита `release`; секрет подписи в окружении отсутствовал, независимое восстановление ключа не подтверждено. Это проверяемое состояние подготовки, не обещание уже работающего канала. [Защита и ограничения](docs/v1.11-release-hardening.md), [актуальный аудит](docs/release-protection-setup.md), [протокол выпуска](docs/update-release-protocol.md).

Для перехода с v0.10.13 и более ранних выпусков один раз установите актуальную подписанную версию обычным способом: прежние версии ещё не содержат механизма обновления. Начиная с v1.11 следующие совместимые выпуски можно устанавливать из интерфейса после их публикации.

## Безопасное обновление v0.10.13

Версия схемы проверяется до записи. Старый EXE не получает новую рабочую базу: при переходе создаётся отдельная проверенная копия каталога и журналов. Импорт JSON завершается атомарно; ошибки чтения не превращаются в пустые настройки. Старые завершённые журналы можно проверить по SHA-256 в «Операциях»; неоднозначные случаи сохраняют блокировку. Windows CI проверяет состав и запуск уже распакованного ZIP. Подробности, ограничения и результаты: [v0.10.13](docs/v0.10.13-safe-upgrade.md).

## Просмотр и остановка v0.10.12

Чтение выбранной папки выполняется общим координатором с приоритетом перед фоновой сверкой, без отдельного параллельного сканера. После остановки поиска можно открыть конкретную папку, сохранив паузу автообновления остальных корней. Кнопка остановки доступна для этого чтения и ждёт фактического завершения читателя. Клик по исключённой папке не включает её в библиотеку; режим «Подпапки» ограничивает именно текущий просмотр. Подробности и проверки: [v0.10.12](docs/v0.10.12-coordinated-browse.md).

## Поиск и остановка v0.10.11

Первоначальный поиск и автообновление используют общий координатор обхода. Кнопка «Остановить поиск» отменяет поиск и приостанавливает сверку, ожидая завершения настоящих читателей. Случайное обновление интерфейса не возобновляет обход; новый явный поиск или продолжение фоновой обработки запускает его снова. Уже добавленные записи сохраняются, оригиналы не изменяются. Метаданные управляются отдельно в «Операциях». Подробности и проверки: [v0.10.11](docs/v0.10.11-single-scan-stop.md).

## Фоновые задачи v0.10.10

Исправлены повторная сверка большого корня без паузы и полный обход диска из-за изменения небольшой папки. Метаданные читаются из отдельной очереди и сохраняются короткими пакетами. В «Операциях» видны фоновая работа, текущий файл, прогресс и сохраняемая пауза. Новые текстовые `.ts`/`.mts` больше не добавляются как видео; существующие записи не удаляются. Собственный кэш исключён из сканирования и при старом расположении каталога. Подробности и ограничения: [v0.10.10](docs/v0.10.10-background-work.md).

## Поиск и сортировка v0.10.9

Два дополнительных индекса ускоряют группировку результатов поиска и чтение страницы внутри месяца при сортировке от старых файлов к новым. Для небольшой выбранной папки сводка групп использует поиск по индексу пути; для широких корней сохраняется обычный план. Поиск остаётся буквальным поиском подстроки; результаты, правила папок, выделение и восстановление позиции сохраняют прежний контракт. Обновление не удаляет прежние индексы и не переписывает записи медиа. Диагностика отдельно измеряет подготовку, ожидание, группы, позицию, страницу и публикацию. Сравнение выполняется с v0.10.8 на одном Windows-хосте. Подробности и границы проверки: [v0.10.9](docs/v0.10.9-search-sort.md).

## Автообновление v0.10.6

- Файловые события обрабатываются в фоне ограниченными пакетами. Отключение диска, отсутствие файла и запрет доступа показываются отдельно; записи, избранное и известные даты сохраняются.
- Внешнее переименование сохраняет идентичность записи только при однозначном совпадении Windows file ID, размера и даты и подтверждённом отсутствии старого пути. Неоднозначный случай остаётся отдельной записью.
- Потерянные события и переподключение запускают сверку; изменённые файлы теряют устаревшие метаданные, хэши и превью. Проверка версии наблюдения защищает от позднего результата фонового чтения.
- Автообновление наблюдает добавленные папки и текущую просматриваемую папку. Простой просмотр без подпапок не включает рекурсивное сканирование диска.

Контракт и ограничения: [v0.10.6](docs/v0.10.6-library-monitoring.md). Методика сравнения Windows: [performance-comparison.md](docs/performance-comparison.md).

## Быстрое ядро

- Каталог остаётся в SQLite: UI получает сводку групп и страницы около видимой области. Коллекции всех фотографий в главном окне больше нет.
- Дата, папка, сортировка, избранное и поиск применяются запросами в фоне; устаревшие запросы отменяются. Новая папка сразу показывает состояние загрузки.
- Настройки восстанавливаются до показа основного окна; файлы, метаданные и дерево догружаются в фоне.
- Сканирование сохраняет небольшие транзакции, без полной перезаписи каталога. Недоступный диск не означает удаление записей.
- Ограниченная очередь фоновых работ оставляет ресурс для видимых превью. Память декодированных изображений учитывается в бюджете 256 MiB, дисковый кэш — 512 MiB. Это бюджеты кэшей, не предел всей памяти процесса.
- GIF/WebP анимируются в пределах бюджета; для больших анимаций отображается первый кадр с пояснением.
- Галки включают конкретные поддеревья: исключённый диск может содержать отдельно включённую папку. Частичный выбор виден промежуточной отметкой; обычный клик остаётся навигацией.
- HEIC/HEIF: встроенные libheif/libde265 декодируют основной снимок, включая поворот и 48 Мп; отдельный процесс ограничен памятью и временем. Просмотр — 8-бит SDR, HDR/gain map и ICC-only цветопрофили пока не воспроизводятся полностью.
- Диагностика записывает задержки Dispatcher, подготовку вида, очередь и память. Скрипт `scripts/summarize-performance.ps1` считает p95/max; задержка Dispatcher не равна полной задержке клика.

## Безопасная организация

- Ctrl/Shift-выделение, перенос в папку дерева, обязательный предварительный план и подтверждение.
- Совпадение имён: пропустить или подобрать свободное имя; автоматической перезаписи нет.
- План поддерживает папки по году, месяцу, дню, необязательную папку события и префикс имени по дате съёмки. Неизвестная дата попадает в «Без даты съёмки».
- SHA-256, проверяемый журнал, фиксация на диск, повторяемое восстановление, транзакционное обновление каталога. На одном томе используется переименование; между томами — проверенная копия до завершения исходного файла.
- «Операции»: история, продолжение после сбоя, безопасный откат и проверенная резервная копия SQLite.
- Дубли помещаются только в карантин. Сохраняемый экземпляр повторно проверяется и удерживается открытым во время операции.
- В группе точных дублей можно выделить 2–4 копии и сравнить их рядом с синхронным масштабом и перемещением; `K` выбирает сохраняемую копию, `Пробел` меняет отметку карантина.
- Похожие фото являются только подсказкой для ручного просмотра; режим не считает их доказанными дублями и не предлагает массовое удаление.
- Однозначные RAW+JPEG, XMP и AAE перемещаются связанной группой. Неоднозначный Live Photo, ссылки/reparse points и перенос между томами с NTFS ADS/EFS блокируются, чтобы не терять связанные данные.
- Перенос не перекодирует фото/видео и не редактирует встроенные метаданные. Незавершённые операции блокируют новые переносы и карантин до восстановления.

## Проверка и границы результата

Переносимые тесты работают на macOS/Linux; WPF, нативные Windows-проверки и запуск опубликованного EXE проверяет Windows CI. Результат относится к конкретному commit SHA и завершённому запуску workflow. Публикация исходников сама по себе не подтверждает успешный запуск.
Тесты используют синтетические данные. Smoke-проверка создаёт отдельный временный каталог и не открывает пользовательскую библиотеку.
Отключение питания и физическая поломка диска не моделируются; журнал и контрольные суммы не заменяют независимую резервную копию оригиналов.

Результаты, измерения и обязательные проверки Windows: [docs/v0.10.0-validation.md](docs/v0.10.0-validation.md).
Контракт безопасности: [SAFETY.md](src/PhotoShelf.Application/Files/SAFETY.md).
Реальная схема/запросы: [CATALOG.md](src/PhotoShelf.Infrastructure.Sqlite/CATALOG.md).

Для завершённых журналов v0.9.7 доступна проверка файлов и отдельное подтверждение результата; незавершённые/повреждённые журналы требуют ручного разбора. Автоматический перенос или откат старого формата отключён. Не удаляйте `.photoshelf-moving-*`, `.photoshelf-copy-*`, `.photoshelf-retained-*` и журналы вручную. Восстановление файлов выполняйте через «Операции», а не подменой старой базы.

RAW/ProRAW DNG и связывание Live Photo по идентификатору ещё не реализованы. Для HEIC/HEIF показывается основной снимок; AAE-правки не применяются. Видеоплеер использует WPF MediaElement и доступные Windows-декодеры. MainWindow пока сохраняет часть оркестрации UI; полного переписывания приложения не было.

## Сборка и проверка

Нужны Git, .NET SDK **10.0.401** и Python 3 для проверки структуры. `global.json` требует точную версию без roll-forward; CI устанавливает её из этого же файла.
Для Windows-сборки HEIC также нужны Visual Studio Build Tools (C++ x64), CMake и Ninja. Harness сам собирает декодер из закреплённых исходников; пользователю приложения эти инструменты не нужны. LGPL-библиотеки поставляются как заменяемые DLL с исходниками и лицензиями.

```bash
# macOS/Linux: структура, Git hygiene, версия, переносимые тесты
./tools/harness.sh
```

```powershell
# Windows: сборка, все тесты, publish, ресурсы и запуск UI, release ZIP
./tools/harness.ps1
# Дополнительно каталоги 10 тыс. / 100 тыс. / 1 млн записей
./scripts/verify-windows.ps1 -Scale
```

Скрипты не добавляют результаты в Git. Сборки, TRX, журналы и ZIP остаются локальными/CI-артефактами.
Обычная сборка использует `packages.lock.json`. Windows harness публикует с `-p:PhotoShelfPublish=true -p:RestoreLockedMode=true`: отдельные `packages.publish.lock.json` фиксируют граф `win-x64`/single-file, включая неявные SDK-инструменты. При обновлении SDK или пакетов проверяйте и обновляйте оба профиля; CI не пересоздаёт lock-файлы при расхождении. Отчёты зависимостей и аудита публикации сохраняются отдельно.
Старые инструкции упаковки и manifest относятся к архивным поставкам до перехода на GitHub; для актуальной разработки используйте репозиторий.

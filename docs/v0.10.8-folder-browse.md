# PhotoShelf v0.10.8-ultra — просмотр папок и мониторинг

Пользователь сообщил о пустом виде, мигании стартовой панели и высокой нагрузке после выбора папки на другом ноутбуке. На снимке v0.10.7: 498 280 записей каталога, 0 в текущем виде, `C:\Users\Alex`, «Подпапки» выключены. Пользователь подтвердил нажатие на название папки и наличие фотографий непосредственно в ней; отсутствие прямых файлов не считается установленной причиной.

## Подтверждённые проблемы кода

1. Watcher получал рекурсивную подписку даже для нерекурсивного просмотра. События `.log` и других неподдерживаемых файлов занимали ограниченную очередь до проверки расширения. Большой поток таких событий мог приводить к переполнению и принудительной перепроверке медиа.
2. Сверка выбранного корня запрашивала все вложенные записи SQLite, а затем фильтровала их в памяти. Пустой родитель мог потребовать обхода сотен тысяч записей.
3. Даже пустой пакет мониторинга завершался запуском метаданных и общего подсчёта. Изменения медиа в других папках вызывали перестроение пустого текущего вида и переключение видимости стартовой панели.
4. Восстановленная папка обнаруживала новые файлы через общую очередь мониторинга. Выбор во время начальной загрузки мог не запустить отдельное чтение папки.

Это подтверждённые цепочки кода; точный поток событий и производительность пользовательского ноутбука удалённо не измерены.

## Изменения

| До | Теперь |
|---|---|
| Нерекурсивный просмотр слушает вложенное дерево | Рекурсия задаётся отдельно для каждого корня; библиотечные корни продолжают наблюдать подпапки |
| Немедийные файлы расходуют очередь медиа | Расширение проверяется до постановки в очередь; события каталогов обрабатываются отдельно |
| Исключённый диск с включённой дочерней папкой остаётся широким корнем | Наблюдение начинается с включённых папок |
| Проверка прямой папки читает весь вложенный каталог | Keyset по `folder_key,path_key`; добавлен индекс без удаления прежних индексов |
| Пустой batch запускает метаданные/COUNT | Работа запускается после подтверждённых записей; commit перед отменой не теряет завершение |
| Изменения другой папки перестраивают текущую сетку | Обновление ограничено текущим видом, включая старый путь переименованного файла |
| Пустой ItemsSource многократно заменяется пустым | Существующая пустая поверхность сохраняется; индикатор объясняет чтение/фильтры/подпапки |
| Восстановленный просмотр ждёт общую очередь | Отдельное порционное чтение папки при запуске |

Галка включает папку в библиотеку. Нажатие на название открывает её. «Подпапки» управляют включением вложенного содержимого в просмотр. Пустой вид больше не предлагает глобальный поиск при наличии большого каталога; он объясняет текущую область и фильтры.

## Проверки и границы

Добавлены регрессии очереди при тысячах немедийных событий, смешанных рекурсивных областей, отмены после commit, прямой выборки среди вложенных записей и SQL-плана без полного прохода/временной сортировки.

Режим `--ui-browse-smoke` использует отдельный процесс, собственные временные каталог и медиа. Он включает production-мониторинг, проверяет пустой родитель, прямое декодированное PNG-превью, впервые выбранную неиндексированную папку, галки, подпапки, быстрое переключение, стабильность при шуме и контрольные суммы исходников. Синтетический MP4 проверяет присутствие видео в списке, а не работу видеокодека.

Точный commit, результаты TRX и JSON сценария поставляются в архиве выпуска. Маковская cross-build не подтверждает WPF runtime; готовность выпуска требует Windows harness. Прежний smoke не включал мониторинг, поэтому его успешность не покрывала данный сценарий.

Отдельной проверки пользовательской библиотеки, всех физических дисков и DPI нет. Значения времени превью и CPU в синтетическом сценарии — измерения этого стенда, не обещание для любого ноутбука. Оригиналы в рабочих операциях мониторинга не изменяются; протокол переноса, карантин, сохранение пользовательских полей и принудительная проверка после реальной потери событий сохраняются.

# PhotoShelf Ultra v1.11.2: проверка обновления из интерфейса

Техническая версия: `1.11.2-ultra`. Тег выпуска: `v1.11.2-ultra`.

## Назначение

Это минимальный проверочный выпуск после публичной версии 1.11.1. Он не добавляет
функциональность и не меняет каталог, медиафайлы, файловые операции, updater-протокол
или ключ доверия. Разница, видимая пользователю после установки, — номер `v1.11.2`
в шапке и сведениях о версии.

Такой состав позволяет отдельно проверить производственный путь обновления:

1. PhotoShelf 1.11.1 находит более новый стабильный подписанный manifest.
2. Пользователь явно запускает загрузку и установку.
3. Updater проверяет подпись, SHA-256, состав пакета и ожидаемую версию.
4. После защищённой передачи запуска активируется 1.11.2.
5. Каталог, настройки и выбранные папки остаются на месте.

## Обязательные проверки выпуска

- версия во всех производственных подписях согласована с `Directory.Build.props`;
- repository gate, portable tests и полный Windows CI успешны;
- exact-SHA пакет, оба updater lifecycle report и performance job относятся к
  итоговому `main` после слияния;
- тег и release `v1.11.2-ultra` до запуска отсутствуют;
- выпуск запускается только от другого участника и проходит owner approval окружения
  `release`; существующий ключ используется только из environment secret;
- workflow создаёт новый тег и assets без перезаписи старого выпуска.

## Ручная проверка на Windows

1. Распаковать и запустить опубликованный `PhotoShelf-v1.11.1-ultra-win-x64.zip`.
2. Убедиться, что в шапке указано `PhotoShelf Ultra v1.11.1`.
3. Открыть настройки обновлений и нажать проверку обновлений.
4. Убедиться, что предложена версия `1.11.2`, затем скачать и установить её.
5. После автоматического перезапуска проверить `PhotoShelf Ultra v1.11.2`.
6. Проверить, что библиотека, отмеченные папки, избранное и настройки сохранились.
7. Закрыть приложение и снова открыть его прежним ярлыком: должна запускаться 1.11.2.

Тест выполняется на копии или обычной библиотеке только как проверка чтения и сохранения
каталога. Перенос файлов и карантин дублей для этого сценария не требуются.

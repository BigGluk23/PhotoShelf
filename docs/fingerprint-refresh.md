# Повторный проход индексации похожих фото

Если файл добавлен или изменён во время прохода и его путь уже пройден keyset-курсором,
требуется ещё один проход. Ранее `finally` вызывал `StartPerceptualFingerprintIndexing`
до завершения собственной `_fingerprintTask`. Проверка `IsCompleted` снова выставляла
pending-флаг и возвращалась; задача завершалась, оставляя запрос без исполнения.

Теперь `finally` ставит один callback на Dispatcher с приоритетом Background. Он
исполняется после возврата текущей задачи, проверяет наличие запроса и вызывает обычный
Start со всеми актуальными guards. Накопленный запрос потребляется в Start только после
проверки guards и завершения предыдущего работника. Явный запуск, опередивший callback,
также потребляет запрос: старый callback не создаёт лишний пустой проход.

## Сохранность

- Не заменять `_fingerprintTask` на `Task.CompletedTask` внутри работающего прохода.
  Пауза и файловые операции должны дождаться реального завершения читателя, включая
  синхронный декодер, который ещё не вернулся после отмены токена.
- Между завершением и callback состояние могло измениться: пауза, перенос, незавершённое
  восстановление и закрытие блокируют новый старт. Pending сохраняется до допустимого
  запуска; разрешённый запуск объединяет все накопленные запросы.
- Декодирование остаётся в BackgroundWorkScheduler с прежним приоритетом и бюджетами.
  Внутренний delegate `FingerprintReader` по умолчанию вызывает тот же bounded decoder;
  тесты оборачивают его управляемым read-only дескриптором, затем используют реальный PNG decoder.
- SQL-схема, правила CAS, байты оригиналов и протокол переноса/карантина не меняются.

## Проверки

`PerceptualFingerprintWorkerTests` выполняет девять сценариев на настоящих WPF MainWindow,
Dispatcher, SQLite и фоновых работниках:

1. Новый файл за курсором, 20 повторных запросов, автоматическая обработка и использование кэша.
2. Изменённый уже индексированный файл за курсором, тот же набор гарантий.
3–6. Пауза, перенос, recovery и закрытие устанавливаются между завершением задачи и callback;
запуск заблокирован, pending сохранён, последующий явный запуск не порождает лишний проход.
7–8. Пауза и drain перед файловой операцией ждут отменённого, но ещё открытого Windows reader.
Эксклюзивный доступ к файлу возможен только после его освобождения; возобновление индексирует файл.
9. Production shutdown ждёт читателя и не запускает накопленную индексацию после закрытия.

Сценарии проверяют отсутствие параллельных чтений индексатора и неизменность SHA-256,
размера и mtime тестовых PNG в проверяемых read-only интервалах. Используется только
изолированный TEMP-каталог тестового процесса. Личная медиатека недоступна тестовым stores.

Локальное воспроизведение на macOS связывало неизменённый production worker с реальными
SQLite/scheduler, тестовым декодером и управляемой очередью dispatcher: исходный код
оставлял `a.png` необработанным (exit 1), исправленный — пустую очередь (exit 0). Это
проверка последовательности, не Windows runtime. Кросс-сборка также не заменяет WPF-прогон.
Результаты Windows-тестов относятся только к завершённому CI точного SHA, указанному в PR.

Проверки не измеряют общее ускорение реальной медиатеки и не моделируют физическое
отключение питания. В этом исправлении не добавляется новый протокол файловых операций.

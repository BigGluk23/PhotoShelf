# v1.12: массовые правила точных дублей

## Что изменено

Результат поиска точных SHA-256-дублей остаётся отдельной временной SQLite-сессией.
В сессии теперь сохраняются keeper и отметка карантина каждого файла. Поэтому выбор
переживает смену страниц групп и файлов, но намеренно не переносится в следующий поиск:
новый поиск заново подтверждает состав и хэши.

Правила работают сразу по всему снимку:

- оставить файл с самой новой датой изменения;
- оставить файл с наиболее коротким путём;
- предпочесть файл из выбранной папки или её подпапок;
- отметить либо снять отметку со всех файлов, кроме keeper.

Внутри выбранной группы можно выделить 2–4 файла с `Ctrl`/`Shift` и открыть сравнение.
Масштаб (25–400 %) и перетаскивание синхронны во всех ячейках, поэтому одинаковый
фрагмент остаётся на одном месте. Колесо меняет масштаб, `R` возвращает режим
«вписать», `Esc` закрывает окно. В списке `K` назначает единственный выделенный файл
keeper, а `Пробел` атомарно ставит или снимает отметку карантина с выделенных extras.
После действия остаётся выбрана та же группа, а не первая группа страницы.

Для точных дублей разрешение и встроенные метаданные совпадают побайтно, поэтому они не
используются как ложный критерий «лучшего» файла. Визуально похожие, но разные файлы не
участвуют в массовом карантине.

## Безопасность карантина

Перед изменением файлов UI читает ограниченный снимок выбора и показывает полный план,
включая companions и пропуски. Лимит одной команды — 50 000 отмеченных файлов; общий
FileMoveService дополнительно проверяет лимит после раскрытия companions.

Большой план выполняется порциями по 128 групп точных дублей. Для каждой порции keeper:

1. открывается только для чтения без write/delete sharing;
2. повторно проверяется SHA-256 из поисковой сессии;
3. остаётся открытым до безопасной границы FileMoveService;
4. освобождается до следующей порции, чтобы число дескрипторов не росло с библиотекой.

Каждая порция получает отдельный create-new durable-журнал. Завершённые порции доступны
для отката, а ошибка или отмена оставляет точное место продолжения в «Операциях».
Оригиналы не перекодируются, назначения не перезаписываются, прямого удаления нет.

## Ограничения проверки

Тесты сессии используют только синтетические пути и проверяют страницы, массовые правила,
смену keeper, сохранение полного решения и атомарное множественное выделение. Полный WPF/Windows/HEIF и файловый lifecycle
должен пройти обязательный Windows CI для точного commit SHA. Process-kill не моделирует
отключение питания или физический отказ накопителя.

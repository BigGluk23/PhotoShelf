# PhotoShelf Ultra v0.10.12 — единый обход выбранной папки

## Проблема

В v0.10.11 явный поиск уже выполнялся через `LibraryChangeCoordinator`, но обычный клик в дереве запускал отдельный `PhotoScanner`. Он мог перечислять ту же папку одновременно с монитором. После Stop новый browse был разрешён, однако кнопка остановки оставалась недоступной из-за `_searchStopped`.

## Изменение

| Сценарий | v0.10.11 | v0.10.12 |
|---|---|---|
| Открытие папки | Самостоятельный сканер и возможный параллельный обход монитором | Приоритетный запрос общего координатора; один callback за раз |
| Stop → открытие папки → Stop | Чтение запускается, кнопка Stop отключена | Чтение выбранной папки доступно и отменяемо; автообновление остальных корней остаётся на паузе |
| Быстрая смена папок | Последовательная цепочка отдельных сканеров | Устаревший foreground-запрос отменяется; следующий ждёт фактического завершения читателя |
| Папка внутри рекурсивной библиотеки | Browse мог добавить дублирующий watcher/обход | Используется покрывающий watcher; глубина foreground задаётся отдельно |
| Исключённая папка | Просмотр не должен менять включения | Этот контракт сохранён; запрос не наследует область родительской библиотеки |

`LibraryBrowseTarget` фиксирует путь и режим подпапок. `ConfigureAndBrowseAsync` регистрирует запрос атомарно с конфигурацией и возвращает отдельный ticket завершения. Конфигурационная задача не ждёт сам обход: это предотвращает цикл ожидания при Stop/закрытии.

Приоритетный запрос может прервать фоновую сверку с сохранением её незавершённого намерения. После возобновления фон имеет право повторно проверить уже посещённую часть прерванного корня: это безопасное восстановление, а не обещание строго однократного чтения каждого файла за весь сеанс.

## Сохранность

- Обход использует только чтение оригиналов. Перенос, карантин, схема базы и recovery-журнал не меняются.
- Отмена не удаляет строки каталога и не отменяет уже подтверждённые изменения. Завершающая публикация committed-результатов сохраняется.
- Клик по папке не изменяет правила включения и список библиотечных корней. Выключенные «Подпапки» ограничивают foreground прямыми файлами.
- Пауза ждёт реального выхода callback; перед переносом/закрытием действует тот же барьер завершения читателей.
- События, пришедшие после начала обхода, остаются отдельным намерением. Узкий запрос не подтверждает сверку всего диска.

Добавлено 26 случаев: 15 для координатора, 7 WPF-сценариев и 4 для синхронизатора с настоящей SQLite. Проверяются один обход вместо двух, Stop после нового browse, ожидание настоящего открытого читателя, смена A→B, рекурсивный/нерекурсивный просмотр исключённой папки, сохранность SHA-256/mtime оригиналов и AssetId/избранного/дат уже записанных строк. Отдельные барьеры проверяют Resume во время foreground и возврат присоединившегося поиска в очередь после отмены/ошибки.

Локальная проверка текущего кода на macOS: полная сборка — 0 ошибок, 0 предупреждений; Application — 289 passed / 15 Windows-only skipped, SQLite — 139 passed, Domain — 4 passed. Проверки инструментов — 9 harness + 20 performance reporter passed; repository validation и `git diff --check` успешны. Независимое статическое ревью не выявило оставшихся блокирующих замечаний в этой области. Локальная сборка не заменяет Windows runtime-проверку, результаты которой приведены ниже.

Физическое отключение питания и реальная личная библиотека пользователя не моделируются. Отмена остаётся кооперативной для синхронных вызовов файловой системы; таймаут не используется как разрешение переносить ещё открытый файл.

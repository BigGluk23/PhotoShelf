# PhotoShelf Ultra v0.10.4 — дерево и HEIC

## Изменения

| Сценарий | v0.10.3 | v0.10.4 |
|---|---|---|
| Снять C:\\, включить C:\\Фото | Включался весь диск: удалялось исключение родителя | Включается только выбранное поддерево; родитель имеет промежуточную отметку |
| Перезапуск, нераскрытые папки | Только список исключений | Включения и исключения сохраняются; самое вложенное правило определяет состояние |
| Несколько быстрых отметок | Прерванное сканирование могло потерять прежний выбор | Отменённые корни остаются в очереди до завершения актуальной операции |
| HEIC/HEIF без расширений Windows | Превью зависело от системного WIC-декодера | Встроенные libheif 1.23.5 + libde265 1.1.3; основной снимок, поворот, сетка и просмотр |
| Метаданные HEIC | Отсутствие даты могло доходить до WIC | EXIF-дата и отсутствие даты обрабатываются без WIC |
| Ошибка/зависание HEIC-декодера | Нет отдельного ограниченного процесса | Один worker, Windows Job 1 GiB, timeout 15 секунд, проверяемый протокол вывода |
| Оригинал при декодировании | Чтение файла | Parent удерживает Read/FileShare.Read до фактического завершения worker; SHA256 проверяется в тестах |

Новые настройки добавляются JSON-ключом в существующую таблицу; каталог и прежние исключения не сбрасываются. Просмотр папки кликом по имени остаётся независимым от включения в библиотеку.

Для большого числа правил они компилируются в непересекающиеся диапазоны `path_key`. До 8 диапазонов используется короткий параметризованный фильтр, сохраняющий индекс сортировки; больше — индексный range lookup и rowid lookup. Нет коррелированного обхода JSON-правил на каждую фотографию. Без правил прежний SQL сохраняется.

Измерение на фактической схеме PhotoShelf, SQLite 3.51.0 в памяти на macOS, 50 000 записей и 1 500 правил:

| SQL-операция | Первый корректный фильтр этой разработки | Итоговый фильтр |
|---|---:|---:|
| Count | 7,872 с | 0,0051 с |
| Группы | 7,839 с | 0,0060 с |
| Первые 257 записей | 0,0484 с | 0,0057 с |

Это сравнение двух реализаций нового фильтра, не ускорение всего приложения относительно v0.10.3. Оно не включает UI, дисковый ввод, декодирование и .NET-компиляцию диапазонов. При сложных правилах всё ещё может потребоваться сортировка выбранных кандидатов. Регрессия проверяет результат и EXPLAIN на 50 002 строках, без хрупкого порога времени.

## HEIC: поставка и ограничения

`codecs/heif` рядом с PhotoShelf.exe содержит helper, заменяемые LGPL DLL, полные соответствующие исходники, лицензии и рецепт сборки. Пользователю не нужны HEIF/HEVC Extensions или Visual C++ Redistributable. Кодеки собираются из закреплённых upstream tar с проверкой SHA256; загрузка внешних плагинов отключена. Версии и import table проверяются при сборке.

Декодирование ограничено 128 MiB входа, 64 млн исходных пикселей, 4096 пикселями по длинной стороне результата. Поддерживаются обычные HEVC HEIC/HEIF, основной кадр, встроенные crop/rotation/mirror. 48,771,072-пиксельная синтетическая сетка покрыта тестом. Превью и просмотр не перекодируют оригинал, дисковый кэш содержит только производные PNG.

Вывод 8-бит SDR. HDR gain maps и полное ICC-only управление цветом не реализованы; NCLX обрабатывается libheif. AAE-правки, ProRAW DNG и воспроизведение Live Photo как пары остаются отдельными задачами. Поддержка HEIC не добавляет независимый HEVC-декодер видеоплееру.

Worker — изоляция ошибок и ресурсов, не песочница ОС. Содержимое исходника поступает через stdin, путь исходника не передаётся; исходник открывается родительским процессом только на чтение. При отмене/ошибке родитель завершает процесс и ждёт его фактической остановки. Если ОС не подтверждает остановку, блокировка и единственный слот остаются удержаны до фонового завершения. Это не обещание сохранности при физической поломке носителя.

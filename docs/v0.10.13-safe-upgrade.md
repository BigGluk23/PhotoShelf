# PhotoShelf Ultra v0.10.13 — безопасное обновление

## Что изменено

| Сценарий | До | v0.10.13 |
|---|---|---|
| Запуск старого EXE после обновления | Старый writer мог менять ту же базу, не поддерживая новые ключи путей | Рабочая база и журналы впервые копируются в отдельную generation. Старые каталоги сохраняются; старые EXE не знают нового пути |
| Неизвестная/будущая схема | Initialize мог поставить текущий marker поверх неизвестной версии | Read-only проверка до миграции/импорта; неизвестная схема отклоняется |
| Пустая папка Roaming рядом с библиотекой Local | Выбор зависел от существования папки | Учитываются DB/JSON/операции. При двух библиотеках — явный выбор; недоступность/повреждённый selector не превращаются в новую библиотеку |
| Сбой копирования/миграции | Не было отдельного протокола активации | SQLite Backup API включает WAL; настройки/журналы копируются побайтно и сверяются. Manifest и selector публикуются после подготовки. Неоконченная копия не активируется |
| Битый JSON / ошибка посреди импорта | Возможны пустые настройки или частичный импорт, который больше не повторялся | Повреждённый JSON останавливает импорт; строки, недостающие настройки, хэши и completion marker фиксируются одной транзакцией. Существующие записи и избранное не перезаписываются |
| Старый завершённый журнал v0.9.7 | Блокировка без доступной проверки | «Проверить старый журнал» сверяет SHA-256 назначений и отсутствие исходных/временных файлов. Только после подтверждения записывается отдельный результат проверки |
| Ссылки отката после копирования каталога | Абсолютные пути могли вести в старый каталог | Разрешённые ссылки переводятся в новую папку operations без изменения checksummed записей; внешние ссылки отклоняются |
| Неполная распаковка / компоненты HEIF | Ошибка обнаруживалась при чтении снимка | HEIF preflight без открытия фото. Понятное сообщение о восстановлении комплекта; обычный каталог остаётся доступен |
| Проверка Windows-пакета | Smoke до ZIP | Manifest с SHA-256/размером каждого файла, проверка извлечённого пакета до и после startup/UI/browse smoke |

Этот выпуск улучшает безопасность обновления. Проценты ускорения ему не приписываются. Первая проверенная копия требует дополнительного места и времени; работа идёт в фоне с этапом на экране запуска. Последующие запуски используют закреплённую generation. Проверка соответствия путей выполняется один раз на границе старта, а не при каждом рабочем запросе/Initialize.

## Порядок запуска и хранения

1. Закрыть другие копии PhotoShelf. Новый запуск не завершает чужие процессы автоматически.
2. Старт удерживает mutex, Local `startup-v1.lock` и writer lease активного каталога. Исходные DB/JSON/журналы удерживаются открытыми для чтения на время копирования.
3. `CatalogLocation.Discover` проверяет `storage-selection-v1.json` либо прежние Local/Roaming каталоги. Пустые служебные папки не считаются библиотекой. Ошибки доступа и одиночные остатки backup/sidecars требуют разбора. Если selector потерян, но уже есть generation manifest, запуск останавливается для восстановления выбора, без возврата к старому источнику. Это касается и сбоя между публикацией manifest и selector.
4. Источник проверяется read-only. Создаётся `%LOCALAPPDATA%\PhotoShelf\storage-generations\<id>`, выполняются backup/проверка целостности/точное копирование журналов/инициализация/импорт/чтение настроек.
5. `storage-generation-v1.json` и затем selector фиксируются на диск с запретом перезаписи. Только после этого показывается основное окно с восстановленными настройками. Исходный каталог сохранён, не удаляется автоматически.
6. Кэш/диагностика остаются в Local. Все служебные корни, включая сохранённый Roaming и неоконченные generations, исключаются из сканирования/нового карантина.

Не копируйте старую SQLite поверх рабочей generation и не редактируйте selector вручную. После первого обновления старый EXE покажет оставшийся старый каталог: это сохранённая история, а не актуальная библиотека. Не запускайте две версии для переносов над одними медиа. Изоляция служебной базы не изолирует общие фотографии на диске. Проверка имени процесса обнаруживает обычные старые запуски, но не является защитой от произвольно переименованного стороннего приложения.

## Старые операции

Автоматическое исполнение/откат формата v0.9.7 запрещено. Новый инструмент ничего не перемещает: проверяет ровно известный формат, завершённый статус каждого файла, SHA-256, полные пути, отсутствие source/staging/temporary и доступность исходной папки. Неизвестный формат, оборванная запись, превышение бюджета (32 MiB legacy journal), изменённые/недоступные файлы оставляют блокировку.

После подтверждения проверка повторяется, результат публикуется отдельным `.reviewed-<journalSHA>.json`. Он подтверждает состояние на момент проверки; не заменяет резервную копию и не обеспечивает последующее неизменяемое хранение медиа. Изменение журнала обесценивает этот результат. Незавершённый/неоднозначный случай можно экспортировать для ручного разбора. Не удалять журналы и `.photoshelf-*` ради снятия блокировки.

Уже испорченное старым writer соответствие `path` / `path_key` / `folder_key` обнаруживается и останавливает активацию. Автоматического угадывания путей или идентичности записей нет.

## Проверки

До правок и после реализации полная сборка решения прошла без ошибок/предупреждений. Переносимый прогон: Domain 4, Application 319, SQLite 180 passed; 15 нативных проверок Application требуют Windows и явно пропущены на Mac. Python: 17/17. Дополнительная проверка утраты selector и результаты Windows будут зафиксированы после завершения точного CI запуска.

Добавлены проверки неизвестной схемы без записи, отказа при нарушенных ключах путей, atomic rollback/retry JSON, сохранения favorites/settings/hash/cache, выбора Local/Roaming, WAL backup, fault boundaries активации, сохранности исходного каталога, legacy completed/uncertain/torn evidence, отмены, повторной проверки после preview и восстановления прерванного undo через скопированные журналы. Все фикстуры синтетические.

Отдельно проверяются отсутствие/нулевой размер компонентов HEIF, bounded timeout/cancellation/version protocol; изменённые/недостающие/лишние файлы пакета и небезопасные manifest paths. Runtime допускает совместимые заменяемые LGPL-библиотеки, не требует совпадения их SHA с нашим дистрибутивом.

Сборка WPF на Mac не доказывает поведение Windows. Физическое отключение питания, поломка диска, все сетевые файловые системы и произвольные сторонние вмешательства не моделируются. Ошибки должны сохранять исходные данные и диагностируемые незавершённые копии; независимая резервная копия оригиналов остаётся необходимой.

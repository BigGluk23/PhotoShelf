# PhotoShelf v0.9.7: аудит и проверка

## Подтверждено статическим разбором v0.9.6

`MainWindow.RebuildRows` сортировал и группировал весь каталог в обработчике UI; `SaveCatalogState` синхронно сериализовал JSON и вызывал SQLite без отдельного рабочего потока. `LoadInitialCatalogState` блокировал конструктор через `GetAwaiter().GetResult`; `_dateGroupingMode` игнорировал сохранённое значение. `LoadSavedCatalogAsync` перестраивал дерево после каждых 5000 записей. `StartBackgroundCatalogMaintenance` отправлял проверку существования всех файлов обратно в Dispatcher. `PhotoItem.MetadataText` открывал и декодировал изображение при первом обращении UI. Просмотр WebP выполнял декодирование в обработчике выбора. Карантин перемещал файлы синхронно и скрывал ошибки. Это подтверждённые места синхронной работы; длительности подвисаний на Windows не измерялись.

## Архитектура после изменений

- Application: DTO состояния каталога и независимый от UI `FileMoveService` (план/коллизии/исполнение/журнал).
- Infrastructure.Sqlite: desktop-каталог, настройки, кэш метаданных, хэши. Транзакция обновляет все связанные пути. Существующий доменный каталог и миграции сохранены.
- Desktop: снимок параметров запроса, отменяемая фоновая проекция, небольшие пакеты Dispatcher, локальное состояние выбора и drag-and-drop. Код разделён на `MainWindow.Background`, `MainWindow.Moves` и основную оболочку. Полный переход на MVVM не предпринимался.
- Медиа: ограничение двух одновременно выполняющихся декодирований; видимые элементы владеют отменой и кадрами, выгрузка прекращает анимацию. Для обычных миниатюр сохранён дисковый кэш.

Оставшийся технический долг: проекция всё ещё сортирует текущий снимок каталога целиком в рабочем потоке; для миллионов объектов нужен единый SQL query API с keyset-пагинацией и фильтрацией. В текущем релизе ограничены частота пересчётов и применение UI-пакетов; замеров p95 UI latency на Windows нет. Загрузка списка путей идёт постранично, но базовый список модели постепенно занимает память целиком.

## Автоматические проверки

- Исходные v0.9.6 компилируются с восстановленным `Directory.Build.props`.
- Domain: существующие тесты метаданных.
- Application: успешный перенос с проверкой копии и порядком фиксации; появление коллизии после preview; сбой БД с сохранением обеих копий; изменившийся источник; совпадающие имена внутри пакета; год/месяц и отсутствие даты; отмена до начала.
- SQLite: существующая миграция; round-trip всех настроек; пакеты 128/128/44; перенос путей в каталоге/метаданных/хэшах; карантин; пустой каталог как авторитетный источник; 50 000 записей, отмена после первого пакета и сохранение настройки без перезаписи файлов.
- Release publish: автономный `win-x64`, без trimming WPF.

## Обязательная ручная проверка на Windows

1. На тестовой копии каталога открыть 50–100 тысяч файлов, проверить первый экран до окончания загрузки.
2. Во время сканирования быстро менять папки, вводить поиск, переключать даты, размер миниатюр и галки. Старый результат не должен заменять последний выбор; ввод и прокрутка должны продолжать работать.
3. Выбрать дату съёмки, папку, порядок сортировки, масштаб и системные папки; закрыть и открыть. Проверить отсутствие промежуточного сброса.
4. Проверить C:\, пустую папку, отказ доступа, скрытую папку, отключённый диск, переключатель подпапок. Недоступные записи не должны исчезать из каталога.
5. Проверить статический WebP, GIF с прозрачностью/disposal, animated WebP, длинную анимацию с подписью первого кадра, быстрые переходы между фото и видео.
6. Ctrl/Shift выбрать несколько копий файлов, перетащить в дерево. Отменить план, затем выполнить. Проверить совпадения имён, свободное место, права доступа, перенос между дисками, избранное и новые пути после перезапуска.
7. Для дублей проверить все области, повторный запуск без изменения файлов, затем изменить один файл. Проверить массовое выделение, сохранение одного файла в каждой группе и карантин.
8. Проверить EXIF-даты и «Без даты съёмки», переиндексацию после внешнего изменения файла; убедиться, что даты файлов не подменяют EXIF.

## Журнал и восстановление

`%APPDATA%\PhotoShelf\operations\*.jsonl`: каждое событие содержит Source, Destination, Staging, Temporary, Status, Hash, Error. Перед первым переименованием записывается `planned`; после сохранения источника — `staged`; после проверки и публикации копии — `copied_verified`; после транзакции каталога — `catalog_committed`; после удаления staging — `completed`.

При прерывании сначала закройте PhotoShelf и сохраните копию журнала. Для незавершённой записи проверьте существование Source/Staging/Destination/Temporary. Staging содержит сохранённый оригинал. Не перезаписывайте существующий Source. Для `completed` обратная операция должна проверить SHA-256 Destination и отсутствие Source, затем сформировать обратный план и обновить каталог. Для `reconciliation_required` сравните обе копии и состояние каталога: приложение сознательно сохраняет данные при ошибке. Готовой кнопки автоматического отката пока нет.

Каталог не удаляет недоступные файлы при запуске. Карантин исключён из обычного сканирования. AAE/XMP требуют будущей транзакции связанной группы и сейчас явно пропускаются в плане.

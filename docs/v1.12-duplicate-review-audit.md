# v1.12: аудит графического разбора дублей (#3)

Требования задачи #3 сверены с принятыми PR #9–#11 и текущим `main`.

| Требование | Текущее подтверждение |
|---|---|
| Объяснить группу дублей | Заголовок окна прямо определяет группу как файлы одинакового содержимого |
| Тысячи групп без глобальной материализации | Результаты и выбор находятся в owned scratch SQLite; UI читает страницы и агрегаты |
| Одинаковые карточки и прокрутка | Виртуализированные `ListBox` с recycling, фиксированная компоновка карточек и обрезание длинных путей |
| Сравнение 2–4 файлов | Ctrl/Shift-выделение, отдельное окно, синхронные zoom/pan, клавиши `K` и `Пробел` |
| Области поиска | Текущий вид, текущая папка, отмеченные папки, вся библиотека и две выбранные папки |
| Массовые keeper-правила | Новая копия, короткий путь и приоритет папки применяются SQL-запросом ко всему снимку |
| Безопасный карантин | Полный предварительный план, companions, повторная SHA-256-проверка keeper, порции до 128 групп, отдельные durable-журналы |
| Не смешивать похожие кадры с дублями | Визуальное сходство остаётся отдельным read-only режимом без массового карантина |
| Восстановление позиции и клавиатура | Выбранная группа сохраняется после изменения, страницы и keyboard-команды покрыты тестами |

Граница результата: exact SHA-256 разрешает массовый карантин, visual similarity — только
ручной просмотр. Физическое отключение питания не покрыто process-kill тестами. Перед
закрытием задачи требуется зелёный Windows CI точного SHA; локальная проверка без Windows
не заменяет WPF/runtime evidence.

# PhotoShelf Ultra v0.10.1 — исправление запуска

Пользователь сообщил об ошибке **при запуске**: «Предоставление значения для System.Windows.Baml2006.TypeConverterMarkupExtension вызвало исключение». Точный номер запущенной версии и внутреннее исключение не получены. Поэтому нельзя утверждать, что именно этот пользовательский сбой воспроизведён локально.

## Подтверждённый дефект

Иконки и PNG были объявлены как WPF Content, а XAML ссылался на `Assets/...`. В ZIP v0.9.7 внешней Assets нет, хотя эти байты присутствуют внутри single-file bundle. В v0.10.0 внешняя папка уже добавлена, но Content всё равно зависит от способа определения местоположения сборки. Такое размещение ненадёжно для single-file WPF и совместимо с наблюдаемой ошибкой загрузки splash XAML.

Окно LoadingWindow раньше создавалось до защищённого try. Общий обработчик показывал только Message внешнего исключения, терял вложенную причину и позволял остаться процессу без рабочего окна.

## Изменение

- ICO и PNG теперь объявлены **WPF Resource** и входят в PhotoShelf.g.resources. Все окна используют явный `pack://application:,,,/PhotoShelf;component/...`.
- Иконка трея читается из того же встроенного ресурса; возвращается независимая копия Icon после закрытия потока.
- Новый Program.Main перехватывает ошибки инициализации App/темы; весь асинхронный запуск защищён, включая конструкторы и Show обоих окон.
- Неуспешный запуск завершается с кодом 1. Диалог показывает конечную причину и путь к полному журналу со стеком, вложенными исключениями, версией и окружением.
- Журнал: `%APPDATA%\PhotoShelf\diagnostics\errors`. Если запись туда невозможна — `%TEMP%\PhotoShelf\diagnostics\errors`. Ничего не отправляется автоматически.
- Режим `--verify-startup-resources --startup-report <новый.json>` проверяет ресурсы, tray icon, тему и splash. App verification-only явно запрещает доступ к каталогу и запуск сканирования даже при вложенной обработке Dispatcher.

Файловый движок, перенос, карантин и SQLite-схема не изменялись. Оригиналы фото/видео в этих проверках не использовались.

## Проверка

- Решение и новые Windows/WPF-тесты кросс-компилируются на macOS: 0 ошибок/предупреждений.
- Добавлены 3 переносимых теста вложенных исключений, исходного стека и AggregateException.
- Добавлены 4 Windows/WPF-регрессии: ресурсы внутри сборки и отсутствие Content, декодирование обоих pack URI, создание LoadingWindow, работоспособность tray icon после закрытия потока.
- Наличие и байты встроенных ICO/PNG проверяются статически по ресурсам собранной DLL. Это не запуск WPF.
- На Windows обязательно выполнить `scripts/test-startup-package.ps1` с опубликованным EXE, затем `scripts/verify-windows.ps1` и обычный запуск. На текущем Mac Windows runtime недоступен; исправление пользовательского сценария ещё требует подтверждения там.

```powershell
./scripts/test-startup-package.ps1 -ExePath ./releases/PhotoShelf-v0.10.1-ultra-win-x64/PhotoShelf.exe
```

Если обычный запуск снова выдаст ошибку, нужен новый `.log` из указанной папки: он содержит точную внутреннюю причину вместо общей оболочки BAML. Рабочую базу и фотографии для этого присылать не нужно.

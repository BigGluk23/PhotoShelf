# PhotoShelf: сравнение улучшений Ultra

Ниже сохранено историческое сравнение ядра v0.10.0. Изменения v0.10.2 приведены в конце; актуальные результаты проверок — в [v0.10.2-validation.md](v0.10.2-validation.md).

Сравнение составлено 27 сентября 2026 по исходникам v0.9.7 из `.backups/PhotoShelf-v0.9.7-before-P0.zip`, текущей реализации, отчётам тестов и сохранённым SQL-замерам. Приставка Ultra добавлена в название, интерфейс и метаданные сборки; она не обозначает дополнительное ускорение относительно уже выпущенной v0.10.0 без приставки.

## Скорость и расход ресурсов

| Область | v0.9.7 | Ultra v0.10.0 | Практический прирост / доказательство |
|---|---|---|---|
| Большая библиотека | Все PhotoItem находились в коллекции главного окна | Страницы SQL около видимой области; кэш 12 × 24 строки | UI больше не материализует всю библиотеку. Явное массовое выделение и временные placeholders учитываются отдельно |
| Дата, сортировка, папка | Копия полной коллекции на UI, затем полная сортировка/группировка и построение строк в фоне | Запрос SQLite, отмена устаревшего запроса, материализация нужных страниц | Убраны полная копия коллекции и создание всех строк. Ускорение клика на Windows ещё не измерено |
| Сохранение изменённого списка | DELETE всех строк с повторной вставкой каталога | Upsert порциями 256; избранное и метаданные обновляются адресно | Записываются изменения вместо всей библиотеки |
| Просмотр и нижняя лента | В viewer передавался массив всего текущего вида | Запрашиваются 11 соседних элементов | Ограничен объём загружаемых данных просмотра |
| Фоновые задачи | Отдельный семафор на два декодера, без общего приоритета работ | Ограниченная общая очередь, приоритеты и резерв для интерактивной работы | Тяжёлые задачи меньше конкурируют с видимыми превью; эффект на Windows требует замера |
| Кэши | Лимит отдельной анимации; без общего лимита дискового кэша | 256 MiB для учтённых декодированных данных, 512 MiB на диске | Контроль роста кэшей. Это не жёсткий лимит всей памяти процесса |
| Перенос на одном томе | Полная копия даже внутри одного тома | Переименование без второй полной записи, с проверкой SHA-256 | Убрана повторная запись всего файла. Чтение для проверки остаётся; множитель скорости не измерен |

## Безопасность и восстановление

| Область | v0.9.7 | Ultra v0.10.0 | Что стало надёжнее |
|---|---|---|---|
| Журнал после сбоя | Простой JSONL; SHA-256 и flush уже были | Последовательность и цепочка SHA-256 записей, восстановление проверенного префикса | Повреждения и обрыв записи выявляются, неопределённые данные сохраняются |
| Продолжение и откат | Автоматический recovery/undo не реализован | История, продолжение, откат с собственным журналом | Операция восстанавливается после аварии; откат не перезаписывает занятый путь |
| Файлы + SQLite | Обновление пути без устойчивой квитанции повтора | FULL-транзакция, стабильный ID, квитанция фиксации | Повтор согласования после сбоя между commit БД и подтверждением журнала |
| Завершение исходного файла | Удаление staging по имени после проверки | На Windows — через тот же проверенный открытый handle | Закрыта гонка замены файла между проверкой и удалением. Нативное поведение ещё требует запуска на Windows |
| Карантин | Keeper не перепроверялся перед переносом; строка удалялась из каталога | Keeper повторно хэшируется и удерживается открытым; ID, избранное и даты сохраняются | Защита сохраняемой копии и восстановление каталога при откате |
| Связанные файлы | AAE/XMP блокировали перенос | Однозначные RAW+JPEG/XMP/AAE обрабатываются группой | Подтверждённые связи не разрываются; неоднозначный Live Photo блокируется |
| Активные читатели | Отмена не гарантировала окончания синхронного чтения | Ожидание фактического завершения читателей/декодеров затронутых файлов | Меньше конфликтов файловых блокировок при переносе |
| Новая операция после сбоя | Не было общего восстановления с блокировкой новых операций | Незавершённые журналы блокируют новые переносы и карантин | Ошибка не маскируется повторным переносом поверх неопределённого состояния |
| Автоматические проверки | 16 тестов прошли | 110 переносимых тестов, включая 6 принудительных завершений процесса | +94 проверки. Это не процент роста безопасности |

Асинхронный rebuild, отмена, UI-пакеты, настройки до показа окна, SHA-256, отсутствие перезаписи, flush, карантин, GIF/WebP и кэш хэшей уже присутствовали в v0.9.7. Они не выдаются за новые возможности.

## Измеренный прирост при настройке новой реализации

**Следующая таблица сравнивает промежуточные и окончательные индексы новой реализации. Это НЕ замер v0.9.7 против Ultra.** Сопоставимых замеров скорости старого релиза на том же наборе данных не сохранено.

| SQL-запрос на 1 млн записей | Первый вариант индексов | Финальный вариант | Измеренный прирост |
|---|---:|---:|---:|
| Группы месяцев | 1 401 мс | 66,69 мс | ≈21× быстрее; время меньше на 95,2% |
| Глубокая страница | 1 166 мс | 48,50 мс | ≈24× быстрее; время меньше на 95,8% |

Итоговые однократные прогретые SQL-замеры на macOS ARM64 / .NET 10:

| Каталог | Первые 128 | Группы месяцев | Последние 128 по offset |
|---:|---:|---:|---:|
| 10 000 | 0,47 мс | 0,67 мс | 0,88 мс |
| 100 000 | 0,64 мс | 7,04 мс | 5,30 мс |
| 1 000 000 | 0,52 мс | 66,69 мс | 48,50 мс |

Замеры не включают чтение EXIF, декодирование изображений и Windows UI; это не p95. Числовой прирост скорости всего приложения и процент улучшения безопасности не заявляются. Windows UI, пять нативных тестов и двенадцать WPF-тестов ещё не запускались. Отключение питания не моделировалось.

## Изменения v0.10.1 → v0.10.2

| Область | v0.10.1 | v0.10.2 | Проверяемый результат |
|---|---|---|---|
| Фоновая индексация | Замена всей проекции примерно каждые 750 мс при изменениях | Первый блок быстро, затем буфер до границы этапа или ручного обновления | Устранена регулярная замена заполненного вида на каждом малом пакете; политика покрыта тестами |
| Метаданные видимых карточек | Могли запускать полное перестроение | Адресные обновления существующих моделей | Обновление сведений не требует массового сброса превью |
| Положение при перегруппировке | Якорь по порядковому номеру | Якорь по пути файла, подготовка страницы вокруг него | Положение привязано к фотографии; при исчезновении файла применяется резервная позиция |
| Запуск | Ресурсная smoke-проверка отдельно от главного окна | Дополнительно запуск MainWindow с отдельным временным каталогом | Проверяются реальная инициализация UI и отсутствие новых ошибок |
| Поставка | Ручной архив и локальные отчёты | Версионированные исходники, Windows CI и артефакты конкретного commit | Следующий агент может продолжить через git pull; сборочный мусор исключён из Git |
| Сохранность оригиналов при CI | Требовалась ручная дисциплина окружения | UI smoke сам создаёт изолированный каталог; тесты используют синтетические файлы | Проверки не обращаются к личной библиотеке |

Числовой прирост FPS, времени клика и процента безопасности для v0.10.2 не заявляется: нужен сопоставимый замер Windows на одной библиотеке. Исторические ZIP и TRX, упомянутые выше, остаются вне Git.

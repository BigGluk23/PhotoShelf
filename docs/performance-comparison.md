# Воспроизводимое сравнение производительности Windows

`scripts/compare-windows-performance.ps1` сравнивает текущий commit с закреплённым **v0.10.5 `eb832ee4a37802c9d25ce03359a550c9725371b3`**. Оба исходника собираются на одном Windows runner, затем одинаковый измеритель запускается в порядке **baseline → current → current → baseline**. Каждый запуск — новый процесс и новый временный каталог, две прогревочные итерации и 15 измерений на сценарий. Извлечение baseline использует `git archive` в игнорируемую папку `artifacts`, существующие исходники и личные каталоги не затрагиваются.

```powershell
./scripts/compare-windows-performance.ps1          # 100 000 записей
./scripts/compare-windows-performance.ps1 -Million # дополнительно 1 000 000
```

В `TestResults/performance-*` сохраняются четыре JSON на размер каталога, версия ОС/образа runner, процессор, SDK, commit SHA, hash общего измерителя, JSON сравнения и читаемая таблица Markdown. Нельзя сравнивать старый локальный SQL-замер с новым Windows UI или результаты разных машин. Набор метрик, параметры и отпечатки SQL-результатов обязаны совпадать.

После успешного штатного закрытия удаляется только временная фикстура, атомарно созданная самим измерительным процессом; её принадлежность проверяется повторно. При сбое или невозможности подтвердить принадлежность она сохраняется, а JSON сообщает `fixtureRetained` и причину ошибки очистки. Существующие каталоги приложение для измерений не выбирает.

Измеряются:

- SQLite: первая и дальняя страница, дата съёмки, папка, поиск, сводка групп по обеим датам.
- Настоящее WPF-окно и его обработчики: переключение даты/сортировки, поиск и выбор папки. `ack` — от вызова действия до следующего `Input`-приоритета Dispatcher; `first_data_page` — до публикации заполненной страницы в привязанном списке; `layout` — до следующего обновления layout после публикации.
- Пять последовательностей отмены: ранее запрошенный вид должен получить отмену, финальный поиск должен содержать только свои результаты и оставаться актуальным после ожидания.
- Периодические снимки working set, private/managed memory, числа страниц/строк/ожидающих загрузок ограниченного кэша.

Это **тест каталога и подготовки UI**, не декодирования миниатюр, скорости диска, массового импорта, задержки физической мыши или полной отрисовки пикселей. Фикстура содержит записи с отсутствующими синтетическими путями; миллион файлов на диск не создаётся. Начальная массовая вставка выполняется напрямую в отдельный SQLite вне измерений, с реальной схемой/индексами каждой версии. Фоновое обслуживание обеих версий останавливается одинаковым production-методом с ожиданием завершения читателей. Работу мониторинга на настоящих временных файлах проверяют отдельные интеграционные тесты. Обычный CI smoke остаётся отдельной проверкой EXE и декодирования; интервалы его Dispatcher ticks не используются как задержка клика.

100 мс для `ack` и 500 мс для первой страницы — **цели p95**, в таблице честно отмечается их достижение. Регрессия блокирует сравнение, только если медиана ухудшилась больше максимума из 30%, 20 мс для SQL / 50 мс для UI и шести MAD, причём обе текущие медианы процессов хуже более медленного baseline с тем же абсолютным допуском. Цели и статистический допуск не являются обещанием скорости на любом ПК. Память отображается отдельно; отдельный снимок не равен непрерывному пику процесса.

`-ReportOnly` оставляет функциональные проверки обязательными, но не блокирует команду при измеренной регрессии; применять только для диагностики, не выдавать такой запуск за прохождение performance gate. Пакет и safety CI сохраняют собственные проверки независимо от сравнения.

# PhotoShelf Ultra 1.11.3: дополнение к ревью #17

Кандидат содержит исправления после проверки PR #17 (`6788d40c965ed14a18eddbbc0f05a264e56f3712`).
Схема каталога, доверенный ключ и формат обновления сохранены. Push и PR не публикуют релиз.

## Сохранение пакета до подтверждения запуска

Номер запущенного EXE ещё не означает, что каталог успешно открылся. Раньше UpdateCenter
мог признать пакет текущей версии устаревшим и удалить его до `startup-ready.json`.
Теперь successor с маркерами установщика не запускает GC и не сбрасывает сохранённый stage.

После аварии маркеров окружения уже нет. Startup GC проверяет сохранённые
`program/operations/<request>/request-claimed.json`. Без корректного подтверждения
`startup-ready.json` соответствующие stage, request и view сохраняются, даже если запрос
просрочен. Повреждённый или недоступный claim запрещает очистку. Журналы операций,
установленные версии, каталог и медиа не участвуют в удалении.

Это намеренно консервативное поведение: остатки незавершённой установки могут занимать
место до отдельного разбора. Возраст файлов не даёт права удалять диагностические данные.
После подтверждённого запуска очищается только transport; запись операции остаётся.

## Границы системных каталогов

Исключения Windows, Program Files и ProgramData используют проверку принадлежности
каталогу. Например, `C:\WindowsPhotos` не исключается только из-за префикса `C:\Windows`.
Настоящие системные корни сохраняют прежнюю обработку настройки показа системных папок.
Чтение и сканирование не изменяют исходные фото/видео.

## Проверка отмены SQLite

Регрессия отменяет токен после входа в реальный SQLite VM band-запроса. После отмены
проверяются идентичность записи, повторный поиск, запись fingerprint и `PRAGMA quick_check`.
Внутренний observer устанавливается только тестом и снимается перед возвратом соединения
в пул; публичный API и SQL не меняются.

Проверка чувствительности: временное удаление `sqlite3_interrupt` приводит к падению
этого теста (257 дополнительных VM-callback вместо допустимых 0–32). После восстановления
рабочего кода тест проходит. Watchdog ограничивает ошибочный сценарий, не создавая зависания.

## Валидация и её ограничения

- Locked restore и Release-сборка решения/Windows-драйвера: без ошибок и предупреждений.
- Локально на macOS: Application — 437 passed, 15 Windows-only skipped;
  SQLite — 201 passed (без `CatalogScale`); Python-инструменты — 72 passed.
- Локальные проверки выполняются на синтетических данных; личная библиотека не используется.
- Windows/WPF runtime проверяет CI конкретной ревизии PR. Кросс-сборка на macOS его не заменяет.
- В Windows harness UpdateCenter принудительно инициализируется до startup health в отдельной
  тестовой копии исходников. Пакет полностью проверяется до разрешения health; после него
  ожидается завершение очистки. `unconfirmedTransportPreserved` и `confirmedTransportCleaned`
  обязательны в отчёте для выпуска. Production-программа не получает тестовых переключателей.
- Эти проверки не моделируют физическую поломку носителя или потерю питания.

Версия 1.11.3-ultra готовится как кандидат. Тег, подпись и stable/latest-публикация требуют
отдельного решения и успешных обязательных проверок итогового `main` SHA.

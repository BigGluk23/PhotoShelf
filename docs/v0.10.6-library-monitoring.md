# PhotoShelf Ultra v0.10.6 — обновляемая локальная библиотека

## Что изменилось

| Сценарий | v0.10.5 | v0.10.6 |
|---|---|---|
| Внешние изменения папки | Сверка при запуске и явном сканировании | Фоновое наблюдение, объединение частых событий и периодическая сверка |
| Диск отключён / файл отсутствует / доступ запрещён | Запись сохранялась без явной причины недоступности | Отдельный статус в карточке, просмотре и дереве; даты и избранное сохраняются |
| Внешнее переименование | Старый и новый пути могли стать разными записями | Перенос идентичности только при однозначном Windows file ID, одинаковом размере/mtime и отсутствующем старом пути |
| Позднее чтение метаданных / хэша | Защита по размеру и mtime | Дополнительно версия наблюдения и проверяемая запись SQLite; поздний UI-пакет также проверяет версию |
| Изменение с прежними размером и mtime | Возможен старый хэш или превью | Файловое событие, переполнение и восстановление наблюдения инвалидируют производные данные |
| Отмена после фиксации переименования | Нового сценария не было | Уже зафиксированный путь публикуется в UI даже при отмене следующего элемента |
| Просмотр папки без подпапок | Ограниченное сканирование по явному выбору | То же ограничение сохраняется и для автоматического наблюдения |
| Сравнение быстродействия | Отдельные SQL-замеры без сопоставимого Windows UI baseline | Одинаковый runner: v0.10.5/current на одном Windows-хосте, ABBA, 100k и дополнительный 1M |

Это сравнение поведения. Числовой прирост скорости определяется только завершённым отчётом Windows; новые функции сами по себе не доказывают ускорение.

## Безопасность и границы

Наблюдатель открывает оригиналы только для чтения атрибутов. Синхронизатор пишет только SQLite и производные кэши. Отсутствующий файл не удаляется из каталога. Каталог мигрирует на schema 5 с проверенной резервной копией; существующие записи и пользовательские поля сохраняются.

Windows identity включает идентификатор тома, 128-битный file ID и время создания. Если файловая система не предоставляет identity, найдено несколько совпадений, исходный путь ещё существует или fingerprint изменился, автоматическое слияние запрещено. Это консервативное сопоставление, а не криптографическое доказательство идентичности содержимого. Подтверждённое событие изменения отдельно сбрасывает кэши.

Reparse points и несовпадение физического пути помечаются для проверки, а известные небезопасные пути не отправляются в preview/metadata/hash. Ранее не проверенные строки миграции остаются видимыми. Переносы и карантин используют прежний подтверждённый план, журнал, no-overwrite и проверку SHA-256; перед ними мониторинг приостанавливает обработку и ждёт фактического завершения читателей. Наблюдатели каталогов продолжают собирать ограниченную очередь событий без чтения медиафайлов; обычная пауза не сбрасывает хэши всей библиотеки. Сам монитор никогда не перемещает оригиналы.

Очередь ограничена 1024 путями; пакет наблюдателя — 256 путей, транзакция синхронизации — не более 128. До 32 корней получают watchers, остальные — периодическую сверку. Состояние корней проверяется примерно каждые 30 секунд; полная периодическая сверка — каждые 30 минут. Переполнение и восстановление наблюдения запускают сверку раньше. Это не мгновенная гарантия обнаружения всех изменений файловой системы.

Фоновая сверка не читает содержимое каждого неизменённого файла. Изменения, которые не дали файлового события и сохранили все наблюдаемые атрибуты, могут потребовать ручной переиндексации. После известного разрыва наблюдения производные данные пересчитываются консервативно; это может временно повысить нагрузку.

Физическая поломка диска, отключение питания, вся матрица USB/FAT/exFAT/NAS не воспроизведены. Тесты используют только созданные ими файлы и каталоги. Независимая резервная копия оригиналов по-прежнему необходима.

## Проверка

Новые тесты покрывают ограничение очереди, потерю событий, переподключение, отмену и фактическую остановку читателей, отказ доступа, сохранение пользовательских данных, CAS, неоднозначные identity, карантин, устаревшие кэши и переименование после отмены. WPF-тесты проверяют повторное отображение файла, текущую карточку после переименования и отклонение старого пакета метаданных.

Mac cross-build подтверждает компиляцию. WPF и нативные Windows-проверки должны пройти в Windows CI на публикуемом commit. Результаты находятся в артефактах exact-SHA workflow; пропуски не считаются успешными тестами.

Методика и команды измерений: [performance-comparison.md](performance-comparison.md). Синтетическая база на миллион строк не эквивалентна декодированию миллиона фото: измеряются запросы и готовность страниц интерфейса, отдельно от превью и фонового сканирования.

Локальные проверки: portable harness — 292 passed/0 failed/15 native Windows skipped. После последних тестов смены подписки Application повторно прошёл 205 passed/0 failed/15 Windows skipped; ранее проверенные Domain — 4 passed, SQLite — 85 passed. 9 проверок harness и 8 проверок performance comparator пройдены. NuGet audit и locked restore выполнены; одна первоначальная попытка audit завершилась сетевым timeout и была успешно повторена. Эти результаты не заменяют Windows runtime; финальные TRX и отчёт EXE должны соответствовать commit выпуска.

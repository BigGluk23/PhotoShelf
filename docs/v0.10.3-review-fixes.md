Такой экспорт содержит полные пути и явно отличается от обезличенной сводки.

## Почему библиотека заменена

Официальные [BigTIFF advisory](https://github.com/SixLabors/ImageSharp/security/advisories/GHSA-wmxv-xphr-5c9g) и [TIFF CCITT advisory](https://github.com/SixLabors/ImageSharp/security/advisories/GHSA-jj3q-cwqj-842r) подтвердили необходимость убрать прежний пакет. ImageSharp 4.1.2 был проверен как вариант, но его Release-сборка требует ключ согласно [документации Six Labors](https://docs.sixlabors.com/articles/imagesharp/). Пользователь выбрал замену. Проверка лицензии не отключалась и не обходилась.

Источники новых зависимостей: [SkiaSharp](https://www.nuget.org/packages/SkiaSharp/4.152.1), [MetadataExtractor](https://www.nuget.org/packages/MetadataExtractor/2.9.3). Закрепление версии и чистый аудит отражают известные advisories на момент проверки, а не гарантию отсутствия неизвестных дефектов.

## Проверка

Локально на macOS: Release-сборка решения, 0 ошибок / 0 предупреждений; переносимый harness — 204 passed, 0 failed, 10 явных Windows skips; 9 проверок самого harness. Отдельный NuGet audit всех 9 проектов не обнаружил известных уязвимых пакетов. После этого добавлены дополнительные проверки; окончательный Windows-результат записывается отдельно по SHA.

Два дополнительных синтетических scale-теста прошли. Числа ниже — один запуск на Mac, без сравнения со старым UI:

| Сценарий | Результат |
|---|---|
| Запись 100 000 кандидатов дублей батчами | 1 562 мс |
| SQL-группировка: 25 001 группа | 187 мс |
| Последовательное чтение всех страниц 25 001 группы | 1 216 мс |
| Последовательное чтение всех 50 000 файлов одной большой группы | 6 620 мс |
| Выборочный замер managed heap при тесте дублей | база 2,09 МиБ, пик 20,77 МиБ |
| Проверка SHA-цепочки 100 000 записей журнала, 92,4 МиБ, одно итоговое состояние | 901 мс |
| Выборочный замер managed heap при тесте журнала | база 3,11 МиБ, пик 16,00 МиБ |

Managed heap измерен во всём тестовом процессе и включает временный JSON/test-код; это не RSS, не абсолютный предел памяти и не измерение задержки клика. Сопоставимой базы для заявления «ускорение в N раз» нет.

## Сохраняющиеся границы

- Поломка носителя, потеря питания и полностью скомпрометированная учётная запись не покрываются обычными тестами. Журналы не заменяют независимую копию оригиналов.
- SHA-цепочка обнаруживает повреждение, но не подтверждает автора журнала. Подпись EXE и полный recovery-bundle с внешним backup остаются отдельными задачами.
- Декодеры пока работают внутри процесса. Отдельный ограниченный worker с watchdog остаётся следующим этапом; библиотечный memory budget не равен пределу RSS всего приложения.
- Старый roaming-каталог не мигрируется автоматически: база и история операций намеренно остаются вместе. Старые диагностические файлы могут содержать пути; обезличенный экспорт не включает их.
- Нет сравнимого измерения общей скорости UI v0.10.2 и v0.10.3 на одной Windows-машине. SQL/журнальные замеры не выдаются за ускорение кликов или просмотра.

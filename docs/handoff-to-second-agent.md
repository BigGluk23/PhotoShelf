# Задача для второго агента: синхронизация с GitHub, harness и фиксы обновления UI

Продолжаем PhotoShelf.

Общий репозиторий:

https://github.com/BigGluk23/PhotoShelf

Твоя задача сейчас:

1. Забрать актуальную версию из своего локального проекта.
2. Аккуратно закоммитить все изменения.
3. Запушить в общий репозиторий `BigGluk23/PhotoShelf`, желательно в `main`, если нет конфликтов.
4. Если есть конфликты — сначала подтянуть актуальный `main`, аккуратно смержить, собрать, проверить и только потом пушить.
5. Коммиты должны быть нормальные, не одним мусорным zip-коммитом. Минимум:
   - изменения приложения;
   - harness/CI отдельно, если будешь добавлять;
   - фиксы UI/производительности отдельно, если получится.

Важно: не добавляй в Git сборочный мусор, zip-архивы, `bin/`, `obj/`, `.DS_Store`, локальные базы, кэш миниатюр и прочие временные файлы.

Проверь `.gitignore`, чтобы там были исключены:

*.user
*.suo

## Важный контекст

Ты работаешь на Mac, а PhotoShelf — Windows WPF-программа.

На Mac ты не сможешь полноценно запустить WPF UI. Поэтому harness нужно сделать по уровням.

## Harness

Нужно добавить автоматическую самопроверку проекта.

### 1. Кроссплатформенный harness для Mac/Linux/Windows

Например:

```text
tools/harness.sh
```

Он должен уметь хотя бы:

- проверить, что Git-репозиторий в нормальном состоянии;
- проверить, что не попадают `bin/obj/.DS_Store`;
- проверить структуру проекта;
- прогнать доступные не-Windows тесты, если возможно;
- проверить, что версия в коде/README/заголовке не разъехалась, если это легко сделать;
- вывести понятный итог: `OK` / `failed`.

### 2. Windows harness

Например:

```text
tools/harness.ps1
```

Он должен уметь:

- собрать `PhotoShelf.sln`;
- прогнать тесты;
- опубликовать Desktop-проект;
- запустить `PhotoShelf.exe` на 5–10 секунд;
- проверить, что нет нового crash-log;
- закрыть процесс;
- собрать release zip;
- вывести итог.

### 3. GitHub Actions

Добавь workflow:

```text
.github/workflows/windows-ci.yml
```

Он должен запускаться на `windows-latest` и делать минимум:

- checkout;
- setup .NET 9;
- restore;
- build Release;
- test Release.

Если получится без лишней сложности — добавь publish artifact для win-x64 сборки.

Главное сейчас — чтобы GitHub показывал зелёную/красную проверку.

## Баг новой версии: мерцание и дёрганье превью

Сейчас PhotoShelf обновляет список порциями, метаданные тоже подгружаются порциями, и из-за этого в интерфейсе постоянно мерцают превью/карточки: видно, как новые фотографии вставляются, список пересобирается, превью “щёлк-щёлк-щёлк”.

Нужно исправить UX обновления:

- не пересобирать весь список при каждой маленькой порции;
- не вставлять элементы так, чтобы видимая область прыгала;
- если идёт начальная подгрузка/индексация, новые элементы лучше добавлять в конец текущего списка или буферизовать;
- обновлять UI батчами реже, например раз в 250–500 мс или когда накопилось достаточно изменений;
- если текущая сортировка/группировка требует перестановки, не делать её на каждый файл;
- сделать “тихий” background refresh:
  - пользователь видит стабильный список;
  - снизу статус: `Индексирую: 1234 / 50000`;
  - после крупного этапа можно аккуратно обновить группировку;
  - превью не должны массово сбрасываться и перерисовываться;
- желательно сохранять scroll position/selection при обновлении;
- метаданные должны обновлять конкретные карточки, а не заставлять весь список мигать.

Главная идея: UI должен быть стабильным. Фоновая индексация может идти сколько угодно, но пользователь не должен видеть постоянное дёрганье сетки.

## После изменений

Обязательно:

1. На Mac прогнать кроссплатформенный harness.
2. Если Windows недоступна — честно указать, что WPF smoke не запускался локально.
3. Запушить всё в GitHub.
4. В финальном сообщении указать:
   - commit hash;
   - что изменено;
   - какие проверки прошли;
   - какие проверки не могли быть выполнены на Mac.

После push ничего не присылай zip-архивом. Источник истины теперь GitHub. Главное — чтобы следующий агент мог просто сделать `git pull` и продолжить.

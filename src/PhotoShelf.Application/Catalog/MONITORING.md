# Background observation contract

`LibraryChangeCoordinator` owns the watcher lifecycle and one background callback at a time. It never writes originals or SQLite. The Desktop callback reconciles bounded catalog batches and checks its cancellation token before publishing a view. Do not call the coordinator's lifecycle methods from its callback (the lifecycle waits for that callback).

`ConfigureAsync` copies paths, cancels and drains the previous callback, preserves watchers for unchanged roots and reconciles added roots. Changes to recursion, ignored directories or the `ShouldObservePath` delegate require reconciliation. Supply an immutable, in-memory predicate; reuse its delegate when its rules have not changed. Root configuration must contain actual library/browsing scopes, not every drive merely displayed in the tree.

`PauseAsync` cancels, waits for the actual callback and synchronous probe to finish, then closes watcher handles on a worker. Cancellation alone does not prove that a reader finished. Configuration changes retain an explicit pause. `ResumeAsync` starts a fresh generation and requests reconciliation for all retained roots. `DisposeAsync` drains and closes everything. A blocking OS/network call can delay draining; never begin a file mutation merely because cancellation was requested.

Defaults and bounds:

- At most 4,096 configured roots; exceeding the limit fails explicitly. At most 32 root subscriptions, each with two native watchers (file notifications and directory names), using 24 KiB of native buffers per root. Further roots retain periodic reconciliation and expose `NeedsVerification / WatcherLimitPeriodicFallback`.
- At most 1,024 deduplicated pending paths and 256 paths per callback. Overflow retains the affected root in a bounded FIFO reconciliation queue. One root reconciliation is delivered per callback. A continuously dirty root cannot starve other roots.
- First-event debounce is 250 ms; continuous writes cannot postpone a batch indefinitely. Root availability is probed every 30 seconds; full fallback reconciliation is requested every 30 minutes. A long running callback delays subsequent probes; callbacks must scan incrementally and honor cancellation between I/O operations.
- Native error/overflow events and recovery after an unavailable root or closed/failed watcher force root reconciliation and content invalidation, even if file length and mtime did not change. Resuming after an explicit pause also revalidates because closed watchers could not observe external edits during a file operation. `RevalidateContentRoots` survives cancelled/failed callbacks. Ordinary startup/periodic reconciliation compares known snapshots rather than invalidating all hashes unconditionally. Content edits preserving size/mtime made while the program was closed cannot be identified by metadata comparisons alone.
- File rename notifications include both old and new paths. Directory name notifications require reconciliation; an ordinary file creation does not request a complete root scan.
- `.photoshelf-*` path components and configured internal directories are ignored. They must never be removed as caches.

`FileSystemObservationProbe` performs synchronous, read-only metadata I/O on a worker. It distinguishes `Available`, `Missing`, `RootOffline`, `AccessDenied`, and `NeedsVerification`; failures do not fabricate replacement lengths, dates or identities. It checks ancestor reparse points, opens Windows metadata handles without write access and with `OPEN_REPARSE_POINT`, verifies the physical handle path, and combines 128-bit `FILE_ID_INFO`, volume serial and creation UTC ticks. Unsupported identity APIs and non-Windows systems provide no identity. Identity is a hint for conservative matching, not a content hash: the catalog must also verify that the old path is genuinely missing and reject ambiguous candidates.

Synthetic tests cover real watcher delivery, bounded bursts/overflow, cancellation, reconfiguration, explicit pause during file operations, synchronous drain, retry/fallback, offline reconnect, fairness, and unchanged source bytes/mtime. Windows CI must additionally run native stable-ID and junction tests; portable passes do not prove those Windows contracts.

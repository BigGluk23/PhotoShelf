# PhotoShelf: передача разработки

Текущая версия: **PhotoShelf Ultra v0.10.3** (`0.10.3-ultra`). Windows x64, C#/.NET 10/WPF.
Источник истины — https://github.com/BigGluk23/PhotoShelf, ветка `main`. Продолжение: `git pull --ff-only` и чтение `AGENTS.md`. Не переносите старый ZIP поверх checkout: архивы до v0.10.2 сохраняются отдельно как исторические поставки.

## Задача и история

Согласованы этапы P0: быстрое измеримое ядро и безопасная организация файлов. Пользователь ставит сохранность оригиналов выше скорости переноса. После ошибки запуска добавлены встроенные WPF-ресурсы и полная диагностика. GitHub-история сохранена: локальная Ultra интегрирована поверх upstream `902fbe8`, включая исправления запуска. В v0.10.2 добавляются harness/CI и стабильное обновление сетки во время индексации.

## Архитектура и инварианты

- Desktop получает сводку групп и ограниченные страницы из SQLite. `VirtualPhotoRows` держит кэш вокруг видимой области; viewer получает соседние элементы. Не возвращать глобальную коллекцию всех фотографий.
- `CatalogViewQuery` описывает фильтры/порядок. Фоновый обход использует keyset, случайные страницы — offset с индексами. Устаревшие UI-запросы отменяются.
- `BackgroundWorkScheduler` ограничивает очередь/конкуренцию и сохраняет ресурс для видимых превью. Бюджет декодированных изображений 256 MiB относится к кэшу, не всему RSS.
- SQLite: WAL, synchronous=FULL, короткие транзакции, stable asset ID, адресные обновления, backup перед миграцией, идемпотентные квитанции переноса.
- `FileMoveService`: подтверждённый план, связанные группы, SHA-256, durable-журнал, rename на одном томе / проверенная копия между томами, recovery и undo. Callback каталога может повторяться.
- Windows cleanup привязан к проверенному открытому handle. POSIX fallback сохраняет источник под журналируемым резервным именем; не заменять его обычным удалением по пути.
- Перед переносом ожидается завершение фактических читателей. Незавершённые операции блокируют новые переносы/карантин. Карантин повторно проверяет keeper; прямого удаления дублей нет.
- v0.10.3: единый реестр companions; копия на Windows сохраняет owner/group и DACL до первых байтов, неподдерживаемые политики блокируются. Журналы читаются потоково с лимитами; обратные операции сверяются с исходными по путям, хэшу, размеру и группе.
- Дубли хранятся в отдельной SQLite-сессии и показываются страницами. Keeper проверяется по всей сессии. Не возвращать список всех совпадений в RAM.
- Даты имеют отдельный статус ошибки и время повтора; ошибка чтения не стирает ранее известную дату. Schema 4 мигрируется с проверенным backup.
- ImageSharp удалён по решению пользователя. SkiaSharp и MetadataExtractor не требуют ключа; lock-файлы, NuGet audit и notices входят в сборку.
- Новые установки используют LocalAppData. Старый roaming-каталог и его журналы не разрывать. Карантин имеет явный выбранный путь и сохранённый реестр batch-папок для recovery/undo.
- Одновременные экземпляры защищены mutex и файловым lease каталога. Проверка UI использует собственный временный каталог.
- Иконки/PNG — WPF Resource. Не возвращать startup-зависимость от внешней Assets или Assembly.Location. `PreviewImage.Status` позволяет обычный binding вместо attached-property TypeConverter.

## Проверки

```bash
./tools/harness.sh
```

```powershell
./tools/harness.ps1
```

Windows harness собирает решение, выполняет тесты, публикует self-contained EXE, проверяет его встроенные ресурсы и запускает полноценное главное окно с отдельным временным каталогом. GitHub Actions запускает этот сценарий для push/PR в main. Результаты тестов и сборка доступны в артефактах соответствующего workflow.

Lock-профили разделены: обычные build/test используют `packages.lock.json`, публикация с `PhotoShelfPublish=true` — `packages.publish.lock.json` в каждом из четырёх `src`-проектов. Публикация остаётся в `RestoreLockedMode=true`; её RID и `PublishSingleFile` добавляют собственные зависимости SDK. SDK закреплён на 10.0.401 в `global.json` без roll-forward; CI читает этот файл. Обновляйте SDK и оба набора lock-файлов вместе, не отключайте locked mode в CI. `publish-dependencies.json` и `publish-dependency-audit.json` описывают граф опубликованного приложения.

Подтверждён [Windows CI 36338870245](https://github.com/BigGluk23/PhotoShelf/actions/runs/36338870245) на `5acbbd5`: 155 тестов приложения, включая 21 WPF и 5 native Windows, прошли без пропусков. Опубликованный EXE загрузил главное окно и синтетическое превью, отвечал 6 секунд и штатно закрылся без ошибок. Подробности и границы измерений — в `docs/v0.10.2-validation.md`; для последующих коммитов проверяйте их собственный CI.

На Mac можно собрать WPF, но нельзя этим подтвердить Windows runtime. Native Windows-тесты на Mac явно пропускаются. Не считать пропуски успешными тестами и не выдавать зелёный внешний workflow без просмотра конкретных шагов/отчётов за доказательство.

Используйте синтетические файлы. Нельзя проверять перемещение на личной библиотеке. Обычный process-kill не моделирует отключение питания и физическую поломку диска.

## Оставшиеся ограничения

- Нет сопоставимого измерения задержки UI старой и новой версии на Windows. Исторические 21×/24× — только улучшение SQL-индексов внутри новой реализации.
- HEIC/HEIF/RAW decoding и Live Photo resolver по content ID ещё не реализованы; неоднозначные companions блокируются.
- Reparse/symlink и межтомовый перенос ADS/EFS блокируются. NTFS/FAT/exFAT/USB и физические сбои требуют отдельной матрицы испытаний.
- Старые журналы v0.9.7 требуют ручного разбора. Не удалять `.photoshelf-*`/журналы как кэш и не восстанавливать файлы подменой старой базы.
- Видео использует WPF MediaElement и системные декодеры. Крупные GIF/WebP могут показывать первый кадр с пояснением.
- MainWindow сохраняет часть UI-оркестрации. Улучшать постепенно, без полного переписывания.

`bin/obj`, локальные базы, журналы, ZIP, backups, `artifacts`, `releases`, `TestResults` не входят в Git. Старый `scripts/verify-handoff.py` предназначен только для manifest архивных поставок.
